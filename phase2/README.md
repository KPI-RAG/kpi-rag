## Inputs (read-only)

The scripts read the canonical Phase 1 session split from
`kpi_rag/Models Improvement/Data Splits/` and the parsed raw signals from
`kpi_rag/Models Improvement/Synthetic/` (`raw_kpis.npy`, `raw_meta.csv`).
Step 01 records the SHA-256 of each input in `results/01_baseline/manifest.json`,
so any later change to the data is detectable. No input file is ever modified.

## How to run

```bash
cd kpi_rag/phase2
pip install -r requirements.txt          # only if the versions differ
python scripts/01_freeze_data_and_reproduce_baseline.py   # ~10 min
python scripts/02_model1_threshold.py                     # ~1 min
python scripts/03_model1_fixes.py                         # ~3 min
```

To run on another machine, point `KPI_RAG_ROOT` at the folder that contains
`Models Improvement/` and `data/`:

```bash
export KPI_RAG_ROOT=/path/to/kpi_rag
```

All randomness is seeded (`src/config.py`). Re-running gives identical numbers.

## Evaluation protocol

- **Selection metric:** macro-F1 (Model 2) or OOF precision/recall (Model 1) on the
  training partition, StratifiedGroupKFold by **session**, 5 folds × 5 seeds.
- **Comparing two methods:** Nadeau–Bengio corrected paired t-test over the 25 fold
  scores (Wilcoxon reported as a check). A method counts as better only if p < 0.05.
- **Test set:** 3 held-out fault sessions. It was already used for Phase 1 decisions,
  so it is reported once per step as a *post-hoc* check and never used to choose.
- Augmented or synthetic data may enter training folds only, never validation folds.

## Steps and findings

### 01 — Freeze data, reproduce the Model 2 baseline
All 25 fold scores match the Phase 1 record to 4 decimals: macro-F1 **0.2908 ± 0.0902**.
Integrity checks pass (100% row order, no session overlap, 935 fault windows).

### 02 — Model 1 decision threshold, chosen out-of-fold
- The rebuilt Model 1 reproduces Phase 1's test result **exactly** at t = 0.5
  (TP 269 / FP 1105 / FN 31 / TN 4907; 82.2% of false alarms labelled CCI-Mild by Model 2).
- Out-of-fold, Model 1 is much weaker and **session-dependent**: PR-AUC per fold
  0.84 / 0.26 / 0.57 / **0.02** / 0.81 (pooled 0.066; random = 0.036). At t = 0.5 the
  OOF recall is 0.54, not the 0.897 seen on the 3 test sessions.
- The best threshold per fold ranges from 0.008 to 0.927, so **no single threshold is
  reliable**. The pre-registered rule (t = 0.061) buys recall with ~2x the false alarms.
  **Decision: keep t = 0.5.** The fix has to come from Model 1 itself.

### Two defects found in the Phase 1 Model 1 pipeline (inputs to step 03)
1. **Double imbalance correction.** Phase 1 rebalances Normal:anomaly to 80/20 *and*
   trains CatBoost with `auto_class_weights="Balanced"`, so anomalies are over-weighted
   ~4x. This pushes Model 1 to over-flag.
2. **Feature parsing bug.** The Phase 1 regex reads numbers printed as `1.e-05` as two
   values (`1` and `-5`). This corrupts the BLER features (columns 4-7, 12-15) of
   492 training windows (1.9%), 487 of them Normal, creating fake BLER spikes.
   `src/data.py` contains an exact replica of the old parser (used only to rebuild
   test features like-for-like) and the correct features from `raw_kpis.npy`.
   The TelecomTS paper (Appendix, p. 21) states BLER lies in [0, 1], so `-5` is impossible.

### 03 — Fixing the two Model 1 defects (2 x 2 design, 5 seeds x 5 folds)

| Variant (OOF mean, t = 0.5) | PR-AUC | Precision | Recall | False alarms / fold |
|---|---|---|---|---|
| phase1 (both defects) | 0.440 | 0.365 | 0.530 | 1175 |
| fix_features | 0.442 | 0.375 | 0.532 | 1171 |
| fix_weighting | 0.498 | 0.445 | 0.494 | 1020 |
| **fix_both** | **0.492** | **0.440** | **0.499** | **1021** |

- Fixing the weighting cuts false alarms in **25/25 folds** (−13%) and raises PR-AUC in
  18–21/25 folds, at a small recall cost (−0.03). The parser fix alone changes little
  (it touches 1.9% of windows).
- **Not significant** under the pre-registered rule (corrected p ≈ 0.24): one fold
  (sessions 0, 6, 12) scores PR-AUC ≈ 0.02 for every variant, and the corrected test is
  conservative with only 28 sessions. The improvement is consistent but not proven.
- Post-hoc test (3 sessions): false alarms 1105 → 116, precision 0.196 → 0.696,
  F1 0.321 → 0.780, recall 0.897 → 0.887 (3 more missed faults).
- **Recommendation:** adopt `fix_both` as the corrected Model 1. Both changes are bug
  fixes (an impossible feature value, a double-counted weight), not tuned choices, and
  the evidence shows no harm except the small recall trade-off.
- **Open problem:** sessions 0, 6, 12 are near-random for every variant, so Model 1
  does not generalize to them. That, not the threshold, is the main target for step 04.

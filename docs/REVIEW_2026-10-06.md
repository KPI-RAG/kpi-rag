## 2. Findings in detail

### 1.1 — Committed index held 245 test-split documents (P0, fixed)

**Evidence.** Ticket ids are the position in the anomalous list, which equals the global
window index because `data/raw/anomalous/` sorts before `data/raw/normal/`. The committed
index had the *right id set* (935 ids, all in `train_idx`) but the *wrong documents*:

```
chroma doc at id k == current-loader ticket k :   0 / 935
chroma metadata label != ground truth[k]      : 875 / 935
chroma docs by CONTENT -> train: 690, TEST: 245
```

So a test window could retrieve its own ticket. Citation validity is unaffected (tickets
contain no 3GPP references) but C2/C3 *ticket context* and any P@k figure were inflated.

**Fix.** Cleared the collection and rebuilt with `scripts/build_index.py` from `data/raw`.
After rebuild: 935/935 ids match content, 935 train / 0 test, labels == truth 935/935.
Added `test_index_is_train_split_only` (integration) — it would have failed on the old
index with 875 mismatches. `index_tickets()` skips existing ids, so **a stale index must be
cleared before rebuilding**; the build script does not do this for you (open P3: add a
`--rebuild` flag).

Retrieval quality on the clean index (300 anomalous test windows, ground truth from the
handoff file):

| metric | vs predicted label | vs ground truth |
|---|---|---|
| P@1 | 0.92 | 0.64 |
| P@5 | 0.90 | 0.62 |
| P@5, label removed from query | — | **0.05** |

Own-ticket retrieved: 0. Low-confidence flags: 1/300. Top-1 cosine 0.27–0.64 (mean 0.54).

### 1.2 — 13/30 Track C samples are normal windows (P0 for evaluation validity, open)

**Evidence.** `rca_evidence.json` covers window_index 0–1234 = exactly the 1,235
anomalous windows. `layer2_output_sessionsplit.json` holds all 6,312 test windows; only
300 have index < 1235. Track C samples by *predicted* label from that file, so:

```
Track C C3 samples with window_index >= 1235 : 13 / 30
  CCI Mild 3, Buffer Overflow 2, CCI Severe 2, Antenna 2, Handover 2, Doppler 1, Congestion Sudden 1
```

Those 13 windows have no fault at all; the LLM is explaining a false positive, and C3 ran
without RCA evidence for them (that is why only 17/30 C3 prompts had an RCA block).
Layer 2 accuracy on the 300 anomalous test windows is 203/300 = 67.7 %.

**Why it matters.** Track C currently measures "grounding given a prediction", which is a
legitimate deployment view, but the report describes it as an ablation over fault windows.
Mixing the two hides that 43 % of the samples have no ground truth to be right about.

**Recommendation (not applied — changes the experiment).** Sample from the 300 anomalous
test windows (`layer2_rag_handoff_sessionsplit.json`, which carries
`ground_truth_anomaly_type`), stratified by ground truth, and report citation validity
both against the predicted label (what the system did) and the true label (what it should
have done). That also guarantees RCA evidence exists for every C3 prompt. ~15 lines in
`run_track_c()`; then re-run (90 calls, ~12 min).

### 1.3 — Retrieval is a label lookup (P1 design, open)

The corpus has **2 unique `ticket_text` templates** across 935 documents; only the QnA
trace differs per window. The query begins with the fault name, so similarity is decided
by the label: removing it drops P@5 (vs truth) from 0.62 to 0.05 — chance for 11 classes
is 0.09. Dense retrieval is therefore not contributing discrimination; it is re-deriving
the label and inheriting Layer 2's errors (P@5 vs truth 0.62 ≈ Layer 2 accuracy 0.68).

**Best practice.** When the class is already known, filter by it and rank within:
`collection.query(..., where={"anomaly_type": label})` (ChromaDB metadata filter), then
rank by the KPI/SHAP part of the query. That makes the retrieved tickets same-fault by
construction and lets similarity reflect the window-specific evidence. Keep the current
unfiltered path as the C2 ablation if you want to show the difference. Hybrid BM25 + dense
is the usual next step but adds a dependency for little gain on 935 templated documents.

### 1.4 — Documents exceed the embedding window (P2, open)

`all-MiniLM-L6-v2` has `max_seq_length = 256`. Indexed documents are 702 tokens median
(max 1,837); **935/935 exceed 256**. The template `ticket_text` is 11–119 tokens, so the
first part of each QnA trace is embedded and the rest is silently dropped. The team fixed
the model, so the options are: (a) put the window-specific QnA first and the template last,
(b) chunk the QnA and index chunks with the window id in metadata, (c) store a short
LLM-written summary per ticket. (a) is a one-line change in `embed_tickets()` plus a rebuild.

### 1.5 — Ollama payload (P1, fixed)

`/api/generate` reads sampling parameters only from `options`; a top-level `temperature`
is ignored, so the local backend ran at Ollama's default 0.8 instead of 0.1. Also added
`timeout=120` — a hung local server previously blocked the retry loop forever.
Test: `test_call_llm_ollama_puts_temperature_in_options`.

### 1.6 — Two definitions of "valid citation" (P1, fixed)

`validate_citation()` (Track C) requires the spec to be in the fault's alignment row;
`evaluator.score_explanation()` (Track B) only checked the `TS/TR XX.XXX` format, so a
wrong-fault spec would count as valid in Track B. `score_explanation()` now takes an
optional `alignment` and uses the same fault-specific rule; default behaviour unchanged.
Test: `test_score_explanation_fault_specific_with_alignment`.

### 1.7 — Streamlit security config (P1, fixed)

`enableCORS = false` / `enableXsrfProtection = false` were HF-Spaces workarounds. Streamlit
Community Cloud works with the defaults and the app has a file uploader, so the
protections are back on. If the Cloud deploy ever needs CORS off, disable **only** CORS.

### 1.8 — Gemini JSON mode (P2, fixed)

`GenerateContentConfig(response_mime_type="application/json")` asks the model for
machine-parseable JSON instead of relying on prompt wording and fence-stripping. The parser
is unchanged as a fallback. The Track C run in §3 was produced with this setting.

### 1.9 / 1.10 / 1.11 — Dashboard and indexing hygiene (fixed)

- One cached `get_model()` in `kg_indexer`, shared by indexing and querying.
- `app.py` loaded the 13 MB `rca_evidence.json` twice; now one `RCALoader`.
- In example/upload mode, or for a normal window flagged as a fault, the RCA panel showed
  the first record with the same fault type with no indication. It now says it is a
  representative record and that it was **not** sent to the LLM.
- The KPI panel draws `mean ± std` as flat lines (only window statistics reach Layer 3); its
  title said "Signal Window (128 timesteps)". Renamed to "KPI Window Statistics".

### 1.12 — Circular citation metric in C3 (by design)

`validate_citation()` checks the output against the table that `build_prompt()` injected.
C3 therefore measures prompt compliance, not knowledge. This is stated in the README, in
`build_prompt()` and in the interview guide (§7.2); C1 is the intrinsic-knowledge baseline.
Acceptable for the RQ ("does grounding make the citation reliable"), as long as it is
never described as the LLM "knowing" the standard.

"pending"`, `"validated_by": []`, `affected_kpis` empty. The proposal required two-member

### 1.14 — Dependency pins (open)

## 3. Track C after this review

Re-run on the clean index with Gemini JSON mode (`gemini-3.5-flash-lite`, seed 42, same
30 windows as before):

| Condition | Valid citations | Templates | of which via a secondary spec | anomalous windows (17) | normal windows flagged (13) |
|---|---|---|---|---|---|
| C1 label + SHAP | **8/30 = 27 %** | 0 | 7 | 6/17 | 2/13 |
| C2 + tickets | **7/30 = 23 %** | 0 | 5 | 6/17 | 1/13 |
| C3 + alignment + RCA | **30/30 = 100 %** | 0 | 0 | 17/17 | 13/13 |

Controls: same 30 windows in all three conditions, Jamming absent, 0 rate-limit retries,
all 90 responses parsed first time (JSON mode).

Two things to say plainly in the report:

1. **The baselines are noisy.** C1's inputs did not change between yesterday's run (12/30)
   and this one (8/30); the ±4 swing is temperature-0.1 sampling at n = 30. Quote the
   Wilson interval (C1 27 % → 14–46 %), and do not read C1 vs C2 as a difference.
2. **Most baseline "hits" come from secondary specs.** 7 of C1's 8 valid citations are
   TS 38.104 for RF Filters or TS 38.331 for Handover, standards the LLM reaches for by
   default and which Rodina's rows happen to list second. With primary-only matching C1
   would be 1/30. The C2→C3 gap (+77 pp) is robust to that choice; the baseline level is not.

## 5. Design decisions vs. current practice (Layer 3)

| Decision | Verdict | Note |
|---|---|---|
| ChromaDB, persistent, cosine HNSW | sound | right size; cosine is correct for sentence-transformers |
| `all-MiniLM-L6-v2` | adequate, with a caveat | 256-token window truncates every document (1.4) |
| Query = label + SHAP channels + directions | weak | label dominates (1.3); use a metadata filter and let similarity rank the evidence |
| `top_k=5`, threshold 0.35 | acceptable, uncalibrated | 1/300 flagged on test; threshold never swept |
| Train-only index | correct in intent | was broken in the artefact until today (1.1); now guarded by a test |
| Prompt: strict 5-field JSON, temperature 0.1 | sound | JSON mode added (1.8) |
| Retry once-level + Retry-After + jitter + template fallback | sound | fallback always counted invalid |
| Rate limiter singleton in `call_llm` | sound | covers all backends |
| Citation check: regex + fault-row match | sound, circular in C3 | documented (1.12); accepts secondary specs since `b654178` |
| Track C ablation C1→C2→C3 | design flaw in sampling | 43 % of samples are normal windows (1.2) |
| n = 30 per condition | pilot-scale | Wilson CIs are wide; say so |
| Streamlit + `st.cache_resource` | sound | memory-aware for the 1 GB tier |
| Secrets via env / Cloud secrets, `.env` ignored | sound | no secrets in history (checked earlier audit) |
